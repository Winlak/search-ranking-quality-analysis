# Сравнение качества поискового ранжирования

В этом проекте сравниваю два варианта поисковой выдачи: считаю общие метрики и смотрю, на каких запросах результат стал лучше или хуже.

Данные учебные: генератор создаёт запросы, документы и оценки релевантности. Для каждого запроса оба варианта переставляют один и тот же набор из десяти документов. Модель ранжирования здесь не обучается.

## Что проверяю

- NDCG@10, MRR@10 и Success@3 на уровне запроса.
- Разницу между вариантами с парным доверительным интервалом.
- Результаты по платформе, типу запроса и наличию транслита.
- Совпадение расчётов в Python и DuckDB для всех 24 000 пар «запрос — вариант выдачи» с допуском 1e-12.

В генераторе специально задано ухудшение одной группы запросов. Задача анализа — найти его и показать, почему общей средней метрики недостаточно. Числа и графики собраны в [отчёте](reports/analysis_report.md), результат сверки — в [validation.json](outputs/validation.json).

## Структура

```text
src/pipeline.py          генерация, метрики, срезы и отчёт
sql/ranking_metrics.sql SQL-расчёт метрик на уровне запроса
tests/                   unit-тесты формул
outputs/metrics.json     итоговые числа и худшие срезы
reports/                 отчёт с выводами
data/README.md           гранулярность и происхождение данных
```

## Запуск

```bash

pip install -r requirements.txt

```
